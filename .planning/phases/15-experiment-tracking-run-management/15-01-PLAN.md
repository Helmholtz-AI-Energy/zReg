<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → log_run() | run_id and output_dir are caller-controlled strings; no sanitization against path traversal |
| subprocess → git | Output of git rev-parse HEAD is treated as a plain string stripped of whitespace |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | log_run output_dir param | accept | Research use case; caller is always a trusted local script. Path traversal risk is negligible for a local evaluation tool with no network surface. |
| T-15-02 | Information Disclosure | git_hash via subprocess.run | accept | git hash is intentionally captured for reproducibility; it is never transmitted. Failure falls back to "unknown" — no exception leaks. |
| T-15-03 | Denial of Service | Path.mkdir + json.dump on bad output_dir | accept | If filesystem is full or permissions denied, a standard OSError propagates to caller — no silent data loss. Acceptable for a local research utility. |
</threat_model>
