<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML → EvalConfig | User-provided YAML transform_spec dict crosses untrusted-input boundary into pydantic validation |
| EvalConfig → DataFactory | transform_spec dict passed verbatim to augment() dispatch; dispatch keys consumed by zreg.generators functions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering | `transform_spec` dict from YAML | mitigate | pydantic `extra="forbid"` at top-level rejects unknown EvalConfig keys; `transform_spec` itself is `dict | None` (no nested schema validation), but `augment()` only consumes a fixed allow-list of keys ("sigma", "n_outliers", "scale_factor", "rotation_deg", "rotation_axis", "dropout_fraction", "n_new_points") — unknown nested keys silently no-op. Risk surface is bounded by augment() dispatch contract. |
| T-31-02 | Denial of Service | `transform_spec` with extreme values (e.g. `rotation_deg=1e9`) | accept | `augment()` already runs all transforms in finite time bounded by point count; no recursion or unbounded loops. Research-internal CLI, no public attack surface. |
| T-31-03 | Information Disclosure | `_source_dataset` retains reference to potentially large real dataset | accept | DataFactory is a single-process instance owned by EvaluationRunner; no serialization to disk; standard Python GC reclaims on instance teardown. |
</threat_model>
