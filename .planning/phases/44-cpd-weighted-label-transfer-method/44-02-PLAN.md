<objective>
Implement D-01/D-02/D-03: after `AlignmentStage._build_aligned_cloud`'s CPD branch (either the
`StoredTransform` reuse sub-path or the fresh-CPD fallback sub-path) finishes registering a source
frame, compute the CPD posterior (`EstepResult`) at that final registered position using a
throwaway `RigidCPD.expectation_step()` call, and thread it through `AlignResult.estep_results`.
This reuses zreg's own E-step math (no reimplementation) and is a read-only diagnostic — it does
not change any existing `aligned_cloud` output.

Purpose: Produce the CPD posterior that `LabelTransferStage` (Plan 44-03) needs for the
`cpd_weighted` label-transfer method, without duplicating CPD's internal math.
Output: `eval/stages/alignment.py` computes and returns `estep_results`; `tests/test_alignment_stage.py`
has new coverage proving `estep_results` is populated only for CPD-registered frames, plus all 8
existing direct callers of `_build_aligned_cloud` updated for its new tuple return signature.
</objective>
