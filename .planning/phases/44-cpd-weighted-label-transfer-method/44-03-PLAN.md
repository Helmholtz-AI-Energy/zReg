<objective>
Wire `zreg.color_transfer`'s existing `ColorTransferMethod.CPD_WEIGHTED` into `LabelTransferStage`
as a selectable alternative to the hardcoded `KNN_VOTING`, fixing the two bugs identified in
CONTEXT.md along the way: the pmat orientation mismatch (D-04 — `expectation_step()` returns
`(n_source, n_target)` but `transfer_colors` requires `(n_target, n_source)`) and the categorical
averaging problem (D-05 — a literal weighted average of raw class indices is meaningless; must
one-hot encode then argmax). No changes to `zreg.color_transfer` itself.

Purpose: Give the evaluation pipeline a second, CPD-posterior-based label-transfer method,
selectable per-run via `params["method"]` or defaulted from `EvalConfig.label_transfer_method`,
mirroring the Phase 39 `alignment_method` optional-param-with-config-default precedent exactly.
Output: `eval/stages/label_transfer.py` gains `OPTIONAL_PARAMS`, config-default population, an
`align_result` kwarg on `run()`, and a `cpd_weighted` branch in the per-frame loop; new tests in
`tests/test_label_transfer_stage.py` cover the happy path and both error cases.
</objective>
