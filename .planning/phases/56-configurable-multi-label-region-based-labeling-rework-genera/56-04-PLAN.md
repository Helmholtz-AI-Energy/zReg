  <action>
  Add `LabelComponentSpec, LabelSpec` to the `from zreg.data_generation import (...)` block at the top of tests/test_generators.py.

  Add a `TestLabelRegionShapes` class with tests (use `generate_labels(traj, label_specs=[...], mode="deterministic", seed=...)` throughout, single-point-per-frame trajectories built via a `_single_point_traj(xyz)` helper mirroring the deleted `TestSphericalLabelGenerators`'s helper):
  - Voronoi: a point exactly at label 0's voronoi center gets label 0 when label 1's center is far away.
  - Blob: a point exactly at label 0's blob center (sigma=1.0) gets label 0 when label 1's blob center is far away.
  - Cone: a point exactly at label 0's cone pole (sigma=20.0) gets label 0 when label 1's cone pole points in the opposite direction.
  - Mixture (D-11): a label with two components (one blob near the point, one blob far away) still wins over a competing single-component label whose one component is far from the point - proving multi-component mixture aggregation works.
  - Empty frame: `generate_labels` with `label_specs` on a zero-point frame produces a `(0,)` `torch.long` label tensor without raising, for both voronoi and blob/cone shapes.

  Add a `TestLabelAssignmentModes` class with tests:
  - Deterministic mode is argmax: construct two labels' specs such that one is unambiguously closer/higher-scoring, assert every point gets that label_id every time across repeated calls with the same seed (bitwise reproducible).
  - Probabilistic mode samples from a real distribution: with two blob labels of very different distances from a point, assert `label_id` is one of the two valid ids and that across many repeated points concentrated near one blob center, that label is assigned to a majority of them (statistical, not exact-count, assertion — mirrors the deleted `test_gaussian_probability_decreases_with_angle` style).
  - Probabilistic mode with `n_labels` (no `label_specs`) raises `ValueError` mentioning `mode` (simple path does not support probabilistic - see 56-CONTEXT.md D-10).
  - Probabilistic mode with a `label_specs` voronoi component missing `temperature` raises `ValueError` mentioning `temperature`.
  - `label_specs` with non-contiguous/arbitrary `label_id` values (e.g. `{2, 7}`) round-trips correctly - the output label values are exactly the configured `label_id`s, not positional indices.

  Add a `TestLabelGenerationD07Regression` class with the critical regression test:
  - Build a 2-frame trajectory where frame 0 and frame 1 have an identical single point at the same `pos` (e.g. `[1.0, 2.0, 3.0]`). Call `generate_labels(traj, n_labels=5, mode="deterministic", seed=0)`. Assert `torch.equal(result[0]["label"], result[1]["label"])` — this is only guaranteed if region centers are resolved once per trajectory, not redrawn per frame (D-07's exact bug).
  - Repeat with a `label_specs`-based multi-component mixture across 3 frames, same identical-point construction, asserting all 3 frames produce identical labels.
  - A negative-control style comment (not a runnable test) is NOT required, since directly asserting the positive invariant is sufficient and does not depend on knowledge of the old buggy implementation.
