<objective>
Audit the existing ground-truth configs named in 56-CONTEXT.md's canonical_refs (GT-03) so the
`pc["label"]`-vs-`pc["id"]` convention corrected by Plan 56-01 (D-01) is reflected accurately in
every config's documentation, and so nobody mistakes the fully-synthetic ball/bowl configs'
currently-degenerate constant-label placeholder for a meaningful F1 accuracy signal.

Purpose: `kobitski_ew06.yaml` currently contains a backwards claim ("unlike Shah's `id` which
carries real small-integer class labels") that this phase's own D-05 finding directly
contradicts (it's Shah's `label` field, not `id`). Left uncorrected, this stale comment would
mislead the next person to touch these configs. Separately, the 5 `stage2_label_transfer/*/
synthetic.yaml` configs source their ground truth from a CSV whose `label` column is currently a
hardcoded constant (`scripts/generate_datasets.py:239`) — under Plan 56-01's new `"label"`
default this produces a trivially-maximizable single-class F1, which needs to be documented as a
known placeholder rather than silently fixed (CONTEXT.md's Claude's Discretion note: wiring a
real multi-class label source risks introducing per-frame temporal-labeling incoherence via
`generate_labels()`'s independently-randomized per-frame Voronoi partitions, and risks creeping
into Phase 57's synthetic-generation-mechanism territory — out of this phase's Phase Boundary).

Output: Corrected/confirming comments in the two real-data ground-truth configs, and a shared
audit-note comment block added to the 5 fully-synthetic stage2 label-transfer configs.
</objective>
