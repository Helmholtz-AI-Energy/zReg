- ICP is CPU-only regardless of hardware — EvalConfig raises ValueError at config
  load if device: mps is paired with alignment_method: icp.

  automatically. Functionally correct, slightly slower than CUDA for very large clouds.
- eGNN / PointNet++ on MPS: Supported, but import order is critical on macOS ARM.
  Any custom script that imports these models must import zreg (or scipy) BEFORE
  torch_geometric to avoid a SIGABRT from duplicate libomp initialisation. This is
  handled automatically when using run_eval.py and train_label_transfer.py.
- Learned label transfer training on MPS: train_label_transfer.py auto-detects MPS
  when --device is not passed (resolve_device: CUDA -> MPS -> CPU priority).

2.3 "CUDA / HoreKa cluster" — keep existing content; add:
- GPU-03 (end-to-end verification that AlignmentStage/CPD runs fully on GPU tensors)
  is planned for Phase 53 (not yet verified on real GPU hardware). The code path is
  implemented but cluster GPU smoke-test is pending.
- Recommend search_strategy: auto in configs meant for both laptop and cluster: picks
  propulate when SLURM_JOB_ID is set or MPI world_size > 1, otherwise picks bayesian.
- HoreKa cluster setup requires running scripts/setup_horeka.sh once on the login node
  (loads CUDA 12.x + OpenMPI modules, creates virtualenv, source-rebuilds mpi4py).
- Data must be transferred to the HoreKa workspace before jobs run — see the rsync
  and symlink instructions inside setup_horeka.sh.

**Section 10 "Common pitfalls" — add two new entries after existing entry 8:**

Pitfall 9: "MPS not available" error
- Symptom: RuntimeError from DataFactory at startup when device: mps is set.
- Cause: MPS requires macOS 12.3 or later and an Apple Silicon chip (M1/M2/M3).
- Fix: Either upgrade to macOS 12.3+ or fall back to device: cpu.

Pitfall 10: SIGABRT on macOS ARM when using eGNN or PointNet++
- Symptom: Process aborts with SIGABRT immediately after importing the model.
- Cause: Duplicate libomp initialisation when torch_geometric is imported before zreg/scipy.
- Fix: Do not reorder imports relative to run_eval.py. In custom scripts, import zreg
  (or any scipy-importing module) before importing torch_geometric.

Do not add a device: mps entry to any shipped YAML config (out of scope — configs
deliberately default to cpu). Do not change anything in Sections 1, 3–9.
