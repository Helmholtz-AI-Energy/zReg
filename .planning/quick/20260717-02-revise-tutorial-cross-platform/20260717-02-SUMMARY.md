## What Was Done

### Task 1 — Section 2 rewrite and Pitfall additions

Section 2 "Hardware requirements" was restructured from two loosely organised subsections into three clearly labelled tiers:

**2.1 Any laptop (CPU):** Kept existing content. Added clarification that all shipped configs
default to `device: cpu` and users must explicitly add `device: mps` to activate Apple Silicon
GPU. Added one-line note that `max_points_per_frame: 100–500` is the primary runtime knob.

**2.2 Apple Silicon / MPS (new subsection):** Documents the full MPS picture accurately:
- `DataFactory` checks `torch.backends.mps.is_available()` and raises `RuntimeError` if unavailable
- SWD aligner is fully MPS-compatible (device-agnostic tensor ops)
- ICP is CPU-only regardless of hardware — `EvalConfig` raises `ValueError` at config-load time
- FPS/kNN downsampling: `torch_cluster` activates only when `pos.is_cuda` is True; MPS uses scipy fallback
- eGNN / PointNet++ on MPS: supported, but import order is critical on macOS ARM (libomp SIGABRT)
- `train_label_transfer.py` auto-detects MPS (CUDA → MPS → CPU priority)

**2.3 CUDA / HoreKa cluster:** Kept existing content. Added:
- GPU-03 pending status (Phase 53 — end-to-end GPU verification not yet done)
- `search_strategy: auto` recommendation for dual-environment configs
- `scripts/setup_horeka.sh` one-time setup (CUDA 12.x + OpenMPI modules, virtualenv, mpi4py rebuild)
- Data transfer requirement: rsync + absolute symlink before jobs run

**Section 10 Pitfall additions:**

- Pitfall 9: "MPS not available" RuntimeError — cause (macOS < 12.3 or non-Apple hardware), fix (upgrade or use cpu)
- Pitfall 10: SIGABRT on macOS ARM from libomp — cause (torch_geometric imported before zreg/scipy), fix (correct import order, reference to egnn.py:38–39)
